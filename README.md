## 설치

```
/plugin marketplace add muju0629/hanja-guard
/plugin install hanja-guard@hanja-guard
```

잠깐 끄고 싶으면 `HANJA_GUARD=off claude`.

## 무엇을 잡나

```diff
- 코스피가 上昇했습니다              한자
- 결과，확인했습니다                 중국어 문장부호
- 기본은 꿐져 두고 씁니다             깨진 글자   ← 교정필요!
+ 코스피가 상승했습니다
```

여기까지가 기본값입니다. 원하면 두 개를 더 켤 수 있습니다.

```diff
- 하나로 묶는 게 골자다               어려운 한자어  → 요점
- CJK 범위 regex가 깨졌습니다         설명 없는 전문용어
+ 하나로 묶는 게 요점이다
+ 한자를 찾는 규칙(정규식)이 깨졌습니다
```

<br>

## 깨진 글자는 어떻게 아나

한글로 만들 수 있는 글자는 11,172자인데, **실제로 쓰는 건 2,350자**입니다. `KS X 1001`이라는 국가 표준에 그 목록이 있습니다. 그 밖의 글자가 나오면 거의 항상 오타입니다.

```
꿐  뷁  큵        →  표준에 없음. 오타
꺼  몫  부엌  읊   →  정상. 어려워 보여도 통과
```

가장 정확하게 하기 위해 표준을 그대로 가져왔습니다. 실제 한국어 문서 **211개(124만 자)** 에 돌려서 잘못 잡은 건 **0건**이었습니다.

<br>

## 토큰 사용량의 차이가 있나요?

한 줄 요약: **탐지 되지 않으면 0원, 수정하면 토큰 사용량이 증가합니다.**

같은 질문을 검사만 켜고 꺼서 재봤습니다.

|  | 검사 끔 | 검사 켬 | |
|---|---|---|---|
| 대화 크기 | 18,785 토큰 | 18,785 토큰 | **차이 없음** |
| 걸렸을 때 비용 | $0.1791 | $0.2072 | +15.7% |

훅은 대화 내용에 안 들어갑니다. 그래서 **검사를 통과한 답변은 동일**합니다. 교정이 필요한 경우에만 답변을 한 번 더 만듭니다.

위 수치는 일부러 "한자로만 써줘"라고 시켜놓고 검사를 켠, 일부러 토큰 사용량을 늘려버린 경우입니다. 보통은 하나의 단어정도만 바꾸는 정도라 더 쌉니다.

> 클로드가 얼마나 이런 실수를 많이 하는지는 아직 파악이 안됬습니다. 저도 며칠 테스트해볼건데, 쓰시다가 언제든지 [이슈로 알려주세요](https://github.com/muju0629/hanja-guard/issues).

<br>

| 검사 이름 | 잡는 것 | 기본 |
|---|---|---|
| `hanja` | 한자 | 켜짐 |
| `punct` | 중국어 문장부호 | 켜짐 |
| `broken` | 깨진 글자 | 켜짐 |
| `hard` | 어려운 한자어 | 꺼짐 |
| `jargon` | 설명 없는 전문용어 | 꺼짐 |
| `kana` | 일본 글자 | 꺼짐 |

`hard`와 `jargon`은 사람마다 기준이 달라서 기본은 꺼둡니다.

**`hard` 목록은 분야에 맞게 고치세요.** 바이오 글에서 `저해제`, `유전자 발현`은 정확한 용어라 기본 목록에서 뺐습니다. ex) 금융이면 `상회`, `하회`가 정상이니 넣지 마세요. 목록은 `hooks/guard.mjs`의 `HARD_WORDS`에 있습니다.

아껴 쓰려면 — 안 쓰는 검사는 `detect`에서 빼고, 자주 걸리는 말은 `allow`에 넣고, `maxRetries`를 `1`로 낮추면 최대 비용이 절반이 됩니다.

<details>
<summary><b>멀쩡한 걸 잡지 않으려고 한 것</b></summary>

<br>

이런 도구는 멀쩡한 걸 한 번 잡는 순간 지우게 됩니다.

**내가 물어본 말은 통과합니다.** `日経平均 시황 써줘`라고 물으면 답변의 `日経平均`은 통과하고, 같은 답변의 `上昇`은 걸립니다.

**코드는 안 봅니다.** `print('中文')`은 그대로 둡니다.

**다른 낱말의 일부는 안 잡습니다.** 한국어는 낱말이 붙어서 늘어나기 때문에 그냥 찾으면 틀립니다.

```
대조 대상이 아니라      →  상이 ❌  (대상 + 이)
전통적 비수기인 데다    →  기인 ❌  (비수기 + 인)
임상 2·3상이 진행      →  상이 ❌  (3상 + 이)
계절성에 기인한다      →  기인 ✅  (낱말 첫머리)
```

처음엔 이걸 놓쳐서 실제 문서에서 36건이 걸렸는데, 절반 넘게 이런 오탐이었습니다. 고치고 나니 9건으로 줄었고 전부 진짜였습니다.

**이미 설명한 전문용어는 통과합니다.** `정규식(글자를 찾는 규칙)`처럼 괄호로 풀어썼으면 넘어갑니다.

</details>

<details>
<summary><b>어떻게 동작하나</b></summary>

<br>

두 군데에서 검사합니다.

**답변이 끝난 뒤** — `Stop` 훅이 방금 나온 답변을 읽고, 문제가 있으면 `{"decision":"block"}`을 돌려줍니다. Claude가 같은 자리에서 다시 씁니다.

**도구를 실행하기 직전** — `PreToolUse` 훅이 도구에 넘길 내용을 미리 봅니다. 깨진 글자가 있으면 실행을 막습니다. 파일에 쓰는 내용, 질문 상자에 띄우는 글이 여기 해당합니다.

```
답변 글     :  만들어지는 대로 화면에 나감  →  나온 뒤에 고침
도구 내용물  :  실행 전에 검사 가능         →  보이기 전에 막음
```

도구 내용물에는 `깨진 글자`만 봅니다. 한자까지 막으면 코드에 중국어 문자열을 넣는 정상 작업이 막히고, 이 플러그인 자기 파일에도 시험용 `上昇`이 있어서 **플러그인을 고치는 것 자체가 막힙니다.**

작업이 멈추는 일은 없습니다. 같은 세션에서 2번 막고도 안 고쳐지면 3번째는 통과시킵니다.

</details>

<details>
<summary><b>못 하는 것</b></summary>

<br>

**답변 글은 나온 뒤에 고칩니다.** Claude Code의 훅은 9가지인데 답변이 쓰이는 도중에 걸리는 건 없습니다. 글자는 만들어지는 대로 화면에 나오니까요. 잘못된 답이 잠깐 보이고 곧바로 고친 답이 나옵니다. (도구에 넘기는 내용만 예외로 미리 막습니다.)

**어색한 문장은 못 잡습니다.** 한글로만 쓰였는데 번역한 것처럼 어색한 문장은 규칙으로 못 찾습니다.

**드문 외래어는 잘못 잡을 수 있습니다.** `똠양꿍`의 `똠`이 표준에 없습니다. `allow`에 넣으면 됩니다.

**파일에 쓴 한자는 안 봅니다.** 일부러 그렇게 했습니다.

</details>
